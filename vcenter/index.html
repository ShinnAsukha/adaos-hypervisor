Planned Feature Set

What vCenter will deliver.

Built on the same codebase as the hypervisor panel. The federation primitives are already shipping in v2.7.0 — vCenter wraps them in a dedicated multi-node UI.

Cluster Federation

Aggregate any number of OXware nodes. Single inventory across regions and datacenters. Parallel health checks with per-node drill-down.

API in v2.7

Cross-Node Live Migration

Move VMs between nodes with sub-second downtime using virsh migrate --live. Automatic pre-flight storage and CPU compatibility checks.

Distributed Virtual Switch

vSphere DVS-like overlay. Consistent L2 segments across nodes. Microsegmentation policies that follow the VM as it migrates.

Unified SSO

One SAML / OIDC identity provider for all nodes. Users log in once and switch between clusters without re-authentication.

Aggregated Monitoring

Fleet-wide CPU, RAM, storage, and network metrics in a single dashboard. Alerting and runbook triggers fire across all managed nodes.

Centralised RBAC

Define roles once and push them to every node. Fine-grained per-cluster scope overrides for multi-team datacenters.

Already in v2.7 — the federation API.

vCenter builds on the cluster_federation.py backend module that shipped in v2.7.0. The API is live now — vCenter provides the production-grade UI layer on top.

  • Add/remove members via POST /api/v2/federation/members
  • Parallel health across all nodes in one call
  • Aggregated VM inventory across the fleet
  • Fan-out bulk actions (start/stop/migrate)
  • TLS peer verification per member
